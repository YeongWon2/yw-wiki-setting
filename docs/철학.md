# 위키의 철학

**개인 위키는 내가 생각하는 도구다.** 정답의 주인은 나이고, LLM은 사서다.

| | 개인 위키 (`personal`) |
|---|---|
| 무엇 | 나를 위한 생각 · 기억 도구 |
| 정답의 주인 | 나 (내 말이 가장 높은 근거) |
| 충돌의 뜻 | 대부분 "생각이 바뀜" — 오류가 아니라 기록할 변화 |
| LLM의 역할 | 사서: 정리 · 연결 · 찾기. 내 이해와 판단은 내가 쓴다 |
| 실패 모습 | 모으기만 하고 생각하지 않음 · LLM이 대신 이해함 |

회사 지식의 정본은 회사 도구와 전사 위키다. 개인 위키에는 회사에서 한 일을 걸러 성과(`wiki/career/`)로만 남긴다. 개인 업무 위키(`work`)는 2026-10-29에 없앴다.

## 개인 위키: 생각하는 도구

1. **노트의 목적은 생각이다.** Matuschak은 노트를 모으는 것이 아니라 잘 생각하는 것이 목표라고 본다. 노트는 기본으로 나를 위해 쓰고, 독자는 따로 정할 때만 둔다. → [Write notes for yourself by default](https://notes.andymatuschak.org/zXDPrYcxUSZbF5M8vM5Y1U9) · [Evergreen notes](https://notes.andymatuschak.org/Evergreen_notes)
2. **모으기는 아는 것이 아니다.** Tietze의 "수집가의 오류": 자료를 모으면 쓸모 있게 느껴지지만, 어떤 것에 대해 아는 것과 그것을 아는 것은 다르다. → [The Collector's Fallacy](https://www.zettelkasten.de/posts/collectors-fallacy) · [Matuschak: Collecting material feels more useful than it usually is](https://notes.andymatuschak.org/zQm6XAB3XXrXLHzF7gahpJ2)
3. **LLM이 이해까지 대신하면 내가 못 쓰게 된다.** 2026년 LLM 위키 비판의 핵심은, 형식 정리는 맡겨도 되지만 이해를 맡기면 위키는 좋아지고 나는 덜 알게 된다는 것이다. 중간 길은 "원본 노트는 내가 쓰고, LLM은 그 주위의 위키를 유지한다"는 것이다. → [LLM Wiki and Germane Load](https://braindetox.kr/en/posts/llm_wiki_cognitive_load_2026.html) · [Robots in the garden (Arango)](https://jarango.com/2026/03/27/robots-in-the-garden/) · [The LLM wiki trend has a retention problem](https://pub.towardsai.net/the-llm-wiki-trend-has-a-retention-problem-nobody-mentions-4b376d288e9c)
4. **연결이 분류보다 먼저다.** Bush의 Memex는 기억처럼 갈라지고 겹치는 연결(trail)로 지식을 엮고, 쓰는 길은 굵어지고 안 쓰는 길은 흐려진다고 봤다. → [Memex](https://en.wikipedia.org/wiki/Memex) · [As We May Think (1945)](https://people.ece.ubc.ca/leei/519/bush-1945.html)
5. **노트 상자는 대화 상대다.** Luhmann은 Zettelkasten을 나를 놀라게 할 수 있는 대화 상대로 봤다. 다만 "제2의 뇌"라는 말은 과장이라는 비판도 많다. 노트는 생각을 대신하지 않고 키운다. → [Revisiting Luhmann's 1981 article](https://danallosso.substack.com/p/revisiting-luhmanns-1981-zettelkasten) · [Zettelkasten Forum](https://forum.zettelkasten.de/discussion/comment/18895)
6. **Karpathy의 원래 용도에 개인이 있다.** 개인(목표 · 건강 · 일지), 연구, 독서가 예시이고, 한 사람이나 작은 팀의 지식 기반으로 설계됐다. → [Karpathy LLM wiki idea file 해설](https://agentpedia.codes/blog/karpathy-llm-wiki-idea-file) · [Implicator 분석](https://implicator.ai/karpathys-llm-wiki-got-16-million-views-the-code-isnt-the-point-2/)

## 결정과 충돌

1. **결정은 바꾸지 않고 새로 쓴다.** ADR은 채택되면 고정이고, 생각이 바뀌면 새 ADR로 대체한다. 결정 기록의 위험은 "한 번 쓰고 안 읽는" 위키다. → [AWS ADR process](https://docs.aws.amazon.com/prescriptive-guidance/latest/architectural-decision-records/adr-process.html) · [Fowler: ADR](https://www.martinfowler.com/bliki/ArchitectureDecisionRecord.html) · [Microsoft decision log](https://microsoft.github.io/code-with-engineering-playbook/design/design-reviews/decision-log/)
2. **충돌은 격리하고 사람이 정한다.** 에이전트 기억 연구들은 같은 권위의 다른 출처끼리 다르면 커밋 전에 격리해 사람이 정하게 하고, 기존 기록을 말없이 덮어쓰지 않는다. 자동 수집은 프롬프트 주입 통로이기도 해서, 믿을 수 없는 원천이 검토 없이 위키 페이지가 되면 안 된다. → [MemTX](https://arxiv.org/pdf/2607.23929) · [Memanto](https://arxiv.org/pdf/2604.22085) · [Hyperspell: memory conflict resolution](https://www.hyperspell.com/blog/memory-conflict-resolution) · [ar9av llm-wiki (draft → reviewed)](https://aiagentskills.net/skill/ar9av-obsidian-wiki-llm-wiki) · [nvk/llm-wiki](https://github.com/nvk/llm-wiki)

## 이 세팅에 반영한 것

- 충돌은 위키에 쓰지 않고 `review/`에서 사람이 정한다(결정과 충돌 2번). 결정은 superseded로 잇는다(결정과 충돌 1번). 업데이트는 사람이 말할 때만 한다(개인 2번).
- 원본(`raw/daily` · `raw/notes`)은 내가 쓰고 LLM은 고치지 않는다(개인 3번). 내가 말한 결정은 바로 accepted다(정답의 주인은 나).

## 정한 것 (2026-10-29, v2.1.0에 반영)

1. **개인 위키의 "생각이 바뀜":** 내 생각이 바뀐 것을 충돌(review)로 볼지, Timeline과 superseded 결정으로 바로 기록할지. → 내가 직접 말한 변경은 바로 기록하고, 원천끼리 다를 때만 review로 보낸다.
2. **개인 학습 페이지(강의 개념):** LLM이 이해를 대신 쓰지 않도록 할지. → 개인 위키 concept에 `## My understanding` 칸을 두고 이 칸은 내가 쓴다(LLM은 비워 두고 정리 · 연결만 한다).
3. **개인 위키 고아 페이지:** Memex처럼 안 쓰는 길이 흐려지는 것을 허용할지. → 개인 위키에서는 고아 페이지를 경고만 하고 review로 보내지 않는다.

자료 확인: 2026-10-29. 대부분 블로그 · 포럼 · 프리프린트라 근거 수준이 고르지 않다. Matuschak · Tietze · Bush · AWS · Fowler는 원문이나 1차 자료다.
